Four cores running C programs

Bare-metal C on the full SoC: four out-of-order cores, private L1 caches, MESI snooping bus, shared L2 and main memory. Each program runs on the board-level model of the FPGA (fpga_top, make fpga-sim): the text is decoded from the UART pin as a PC terminal would see it, and the display and LEDs are read back from the board pins. In hello the harts take turns through a shared variable, so each line also shows a store by one core reaching the others through the coherence protocol. In parsum each hart sums a quarter of a shared array; hart 0 collects the partial sums.

Atomics and synchronisation on four cores

In atomics all four harts add 1 to a shared counter 200 times each, three ways. A plain load-add-store loses most of the updates, because the harts overwrite each other. amoadd.w and a spinlock built from lr.w/sc.w both reach exactly 800; the lock line shows which hart held the lock each time. In prodcons hart 0 feeds numbered items through a 16-slot ring buffer to the other three, which claim items with compare-and-swap. Fences order each item before the index that publishes it, and every item must arrive exactly once.

Memory-model litmus tests

Classic two- and four-thread tests (sw/litmus), each run 50 times per copy on the SoC with warmed caches and a random start skew. An outcome the RISC-V memory model forbids must never appear; "allowed" outcomes may or may not, depending on how much this core reorders. Writing these tests exposed one bug, now fixed: two loads of the same address could be performed out of order, which the CoRR rule forbids. Random coherence test

The testbench drives random loads, stores, amoadd and LR/SC straight into the four L1 data caches of the real memory system (make coh-random). It uses 24 lines that collide in both cache levels, so lines are evicted and written back all the time. Every load is checked: no stale value, no value going backwards, and a port's own stores always seen. Every cycle it also checks the single-writer rule (SWMR): a line in M or E is in no other cache. To show these checks have teeth, six designs with a deliberate coherence bug are run through the same test (make coh-mutants), and each one must fail.

Cycles are those of each benchmark's timed region; "Predicted" is the share of hart 0's branches and jumps that were predicted correctly. Dhrystone: 0.25 to 0.75 DMIPS/MHz.

Fitting the Nexys A7-100T

The whole design (fpga_top: four cores, caches, bus, 64 KB memory, I/O) mapped to Artix-7 by Yosys synth_xilinx, before place and route. Yosys usually reports more LUTs than Vivado. The first full-SoC estimate was 88,491 LUTs (140% of the device); moving the cache data, tags and state into block and LUT RAM and simplifying the bus brought it to 53,900 (85%). The performance work of phase P4 (branch prediction, multiply/divide, result holding) added the rest of the figure below.
